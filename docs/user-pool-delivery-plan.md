## 1. 运维基础的最小正确语义

- `/healthz` 是进程HTTP存活探测，不访问DB；`/readyz` 检查存储。在MySQL模式下不是本机owner资格检查；不得把standby摘除。端点存在不等于客户入口已接入。
- 本机诊断 `GET /api/user-pool/diagnostics/local` 是鉴权的内存快照。standby/null、重启后计数归零、某个副本失联不能单独证明全局无owner。结合新鲜的全副本采集与共享库有效任期/DB时间；存储或采集不可用必须能报告“无法确认”。
- 既有监控分别观察无有效调度者持续时间、Ready库存、失败/待修复库存、存储503、耗尽/冷却429以及重启。无owner时Ready库存可能继续服务，但补池/修复停滞；30秒任期不是恢复SLA。
- 核对LiteLLM**实际精确model group**的fallback及关联ID/安全错误码。备用路由不等于恢复调度；不轮换账号绕过429，不自动重放不明推理或已开始的流。
- 终止先摘除新流量再排空。当前源码SIGTERM后约25秒会强制关闭HTTP连接；更长的Kubernetes grace period不会自动让已有长流完整结束。保留此限制，不杜撰drain API或无中断承诺。
- 已有只读适配器30项离线通过，并在本地真实迁移环境实际采集3个独立Proxy和共享MySQL SELECT：`collectionComplete=true`、owner present、paused=true。它证明该次采集有效，**不证明持续owner可用、客户告警送达或跨节点HA**。详见[运维基础](user-pool-ops-basics.md)。

## 3. 真实迁移、UI与两账号的实际状态

历史 `http://localhost:17704/#user-pool` 对应旧SQLite夹具，不能用它或另一套MySQL mock夹具冒充此次真实验收。按用户授权完成的顺序如下；本机仅做功能和迁移，没有容量压测。

1. **源保护和导入已完成。** 原SQLite有4Ready、2统计、25事件、0lease/hold，paused1/target2/cap5。停止旧写入服务，保留原卷及main/WAL/SHM，生成一致性独立备份。初次dry-run因旧schema缺少catalog cooldown表/索引而拒绝；严格copy-only兼容工具15项通过后，仅在新工作副本补已确认缺失的空对象，旧行/字段及原源哈希不变。首次目标连接拒绝亦保留记录；随后空MySQL目标导入4账号/4成员/2统计/25事件并逐字段验证通过。详见[真实迁移记录](user-pool-real-mysql-migration-validation.md)。
2. **多副本UI已核对。** 先一个MySQL Proxy，再扩为三个Proxy＋Console；均ready/storage=mysql，共享4ReadyIdle，一个owner、两个standby。此阶段网络隔离且未启动SSO/Login，用户已查看新UI，未在确认前发起外部开户。
3. **并发配置维护已实测。** 用户批准Prewarm5、Login concurrency2、Login pending2；Login运行并发经版本化API设为2。新离线维护工具31项通过，并通过隔离真实MySQL新配置接受/旧配置拒绝校验。真实池在暂停、排空、停止全部3个Proxy及Login/SSO、确认owner到期后，CAS仅更新配置fingerprint（原Prewarm/pending为1/1，新值5/2），逐表校验全部其它数据保留。不是清空owner、禁用fence或直接覆盖hash；首个合成验证因缓存store造成的断言失败及修正记录保留。
4. **恰好两个真实新账号已完成。** 用户查看UI并批准后，保留原4成员，cap6/临时target6；总114.099秒新增2个Ready成员，未创建第三个。两条Login任务区间重叠，分别89.236/91.784秒，均attempts=1首次成功，完成SSO/SCIM/席位/OAuth/warmup，结束重新暂停。详见[两账号记录](user-pool-real-mysql-two-account-validation.md)。
5. **后续四key功能验证已完成，最新状态不是6idle。** 用户要求target恢复2后，经LiteLLM容器→**Proxy1直连**→共享MySQL，四把virtual key四次请求均HTTP200/completed，对应4个不同成员/active lease；hold/catalog hold排空。最新total6、leased4、ready_idle2、target2、cap6、paused1、leaseTTL172800。测试key全部撤销，Proxy租约保留、按TTL自然过期；撤销key不等于释放租约。详见[四key记录](user-pool-real-mysql-four-key-validation.md)。

源SQLite、旧账号、外部席位、原组件卷/证书未被删除。后续任何新增账号、真实模型调用、配置改变、停启或回退仍须相应批准；上述实测不是无限后续授权。此本地直连Proxy1路径**没有经过负载均衡**，三副本共享状态检查不等于客户Service流量分发/HA验收。
