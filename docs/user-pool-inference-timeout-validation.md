# 用户池推理超时验证报告

## 结论与变更范围

本轮验证支持将推理请求超时与用户池共享配置分离，并验证旧、新进程混用同一测试 MySQL 时，长 Messages SSE 请求的 hold 保护、取消传播和结束清理行为。

实现涉及以下四个文件：

- `src/proxy/src/userPool/inferenceTimeout.ts`（新增）
- `src/proxy/src/userPool/runtime.ts`
- `src/proxy/src/userPool/store.ts`
- `src/proxy/src/userPool/mysqlStore.ts`

新环境变量 **`POOL_INFERENCE_TIMEOUT_SECONDS`** 接受 **5–600 秒**；未配置时回退到旧的 `POOL_REQUEST_TIMEOUT_SECONDS`。新设置不进入共享用户池配置指纹。本文仅记录已提供的实际执行结果，不把测试代码已写好、静态自检或尚未回报的测试计为执行通过。

## 真实时间长请求结果

四个场景均属于 **Messages SSE** 长请求验证。流量阶段共 **601.714 秒**，不是各行耗时相加后的串行执行时间。

| 场景 | 请求端观测 | 模拟上游观测 | 结果 |
| --- | ---: | ---: | --- |
| 5 秒客户端取消 | 约 5 秒 | 4.965 秒 | 取消传播到上游 |
| 旧进程 120 秒超时 | 120.002 秒 | 119.988 秒 | 旧阈值生效，上游中断 |
| 新进程 350 秒成功 | 350.022 秒 | 350.001 秒 | 长请求成功，成功后续租 |
| 新进程 600 秒超时 | 600.005 秒 | 599.975 秒 | 新阈值生效，上游中断 |

请求端与模拟上游分别计时，表中差值不作为额外等待或重试的证据。验证结果为每请求仅一次上游调用，无透明重放。

### 租约与 hold 证据

- 使用**预绑定的 60 秒 ACTIVE 租约**，不是 300 秒 provisional 租约。
- 整个实际长请求运行中不修改租约时间戳，等待自然时间流逝。
- 请求进行期间持续通过 API 调用旧进程的存储/释放逻辑，验证租约越过 60 秒到期时间后，仍因 in-flight hold 而不能被回收。不是仅在结束后查询最终状态。
- 客户端取消、旧超时、新成功、新超时结束后，所有 hold 均删除。
- 成功请求续租；失败请求不续租。

这些结果证明了本轮正常运行的旧、新进程之间的 hold 兼容性，不等同于进程崩溃后的 owner 故障转移验证。

## 失败记录、修复与清理

首次夹具初始化失败，原因是测试 MySQL 在 binlog 场景下缺少创建触发器所需权限；失败发生在旧 Proxy 进程启动之前，因此该次不能作为请求行为测试结果。

随后只为新建测试 MySQL 增加 `--log-bin-trust-function-creators=1`，重新执行隔离验证。该设置是测试夹具修复，不是对生产数据库的配置建议。

最终清理结果为 **PASS**，执行证据已保留。总耗时（含准备、流量、清理）**642.111秒**，流量阶段601.714秒。完整报告已下载并核对压缩包及原文件SHA256：`3e175301d0458f710ec386c8ab1299996eb7d4b44014c2f939c2c439969c20ff`。清理成功与请求验证成功分别记录，不以其中一项替代另一项。

## 尚未覆盖与发布前待办

1. **正式镜像构建与发布**：尚未完成基于固定源码的完整新镜像干净构建、发布及部署镜像核对；现有证据来自四个编译文件覆盖镜像。
2. **客户 Kubernetes 操作**：滚动更新、连接排空及现场部署未实测，不能直接宣称可无损上线。
3. **长 JSON 与其他真实端点**：未执行 350 秒长 JSON 请求。三个推理端点有路由单测，但本轮真实长请求只有 Messages SSE，不能外推为所有端点均已实测。
4. **owner 故障转移**：未验证长请求中 owner 崩溃、接管及故障恢复。
5. **响应头静默等待**：源码分析提示原生 `fetch` 可能仍有独立的约 300 秒响应头等待超时。本轮未实测长时间完全无响应头的上游；**600 秒仅是应用层最大超时，不保证上游静默 600 秒时请求仍存活**。中间代理、入口及客户端也可能有更短限制。
6. **定向 MySQL 与真实时间区分**：3项定向测试已通过，用新代码但旧120秒配置的观察者验证数据库行为；真正的旧镜像共库兼容另由四条实际长流证明。

因此，本轮结论限定为上述隔离环境、镜像构造方式与已列明的实际场景，不代表生产变更、正式发布或所有协议形态的端到端验收。
