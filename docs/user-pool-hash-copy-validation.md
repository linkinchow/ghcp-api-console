# Console 完整 key hash 复制修复验证

日期：2026-09-18。仅修改 Console 显示和复制交互，不修改 Proxy API、数据库、租约、身份 Hook 或真实 key。

## 行为

- Accounts、Leases、Recent events、释放租约确认框共用相同的 CallerHash 显示组件。
- 每个有效hash只提供一个**无边框复制图标按钮**，复制不含 `sha256:` 的完整64位hash，供LiteLLM排查使用。没有第二个Copy caller ID按钮，也不保留下划线文字按钮。
- 页面代码文本保留完整71位caller ID，仅由CSS做视觉截断；选中整段文本可取得完整值，不再复制到字面省略号。
- 悬停或键盘聚焦提示 `Copy hash`；自动剪贴板成功后提示 `Copied`，2秒后自动消失，即使鼠标仍停在图标上也不会常驻。提示绝对定位，不增加表格行高；Escape可关闭提示。读屏成功通知同步清空，卸载时清理计时器。
- 拒绝或缺少Clipboard API时，显示完整64位hash的只读输入框，自动聚焦/选择，提供手动复制途径；失败指引保留到操作恢复或记录刷新，不冒充成功。
- 缺失或格式不合法的hash没有按钮，不把原始异常字符串暴露到title或手动字段。
- hash改变时重建对应复制组件，清除旧成功提示及手动复制字段。复制不调用任何更新、释放或开户API。

## 首轮失败记录

最初双按钮草稿的浏览器测试有2项失败：测试注入函数经TypeScript变换后引用了浏览器不存在的 `__name` 辅助函数，导致剪贴板桩未安装。改为直接注入纯JavaScript测试脚本，不改产品逻辑来放宽断言。随后按用户要求简化为一个Copy hash按钮，并完整重跑7项通过。

独立预览最初对无关Dashboard接口返回的合成数据形状不正确，触发预览错误；修正仅供本地预览的模拟响应后，重新启动并验证无控制台错误。未修改生产Dashboard处理逻辑。

图标交互测试初次仍按旧的有边框草稿断言1px，更新为用户要求的0px；随后发现测试数据多个账号共用GH login导致行选择器匹配3行，改为按准确账号名称选取。没有放宽产品复制/自动消失断言；最终完整8项重跑通过。
