### 历史失败与修复

1. 首轮120秒短测在17.176秒停止，完成五个副本的短亲和性流后首个组合周期失败；清理成功，较长测试未启动。
2. 原报告只保留了后续`Soak aborted`，不能据此判断产品故障。增加有界首因记录后再次诊断，18.162秒停止；首因确定为`child-log / ERROR / upstream-stream-failed`，随后才是sampler/workload取消级联。
3. 对照实际取消路径，计划内客户端取消会由产品记录stream-failed日志，原夹具“任意ERROR即失败”与设计的取消场景冲突。修正版只在精确请求/PID、事先登记且已发出取消、原生上下游已关闭证据、单个IPC/日志配对全部满足时计为预期取消。其余ERROR/WARN和mock异常仍失败，SQL不续租/排空/无重放检查保留。
4. 修正版类型检查、6项离线测试通过，有界独立只读复核无确认阻塞；后续真实短测和持续测试已验证上下文传播及计划取消时序，如上记录，不以离线测试替代。
5. Azure两VM被关停后，曾在上传前被拒绝，未运行负载。用户授权后两VM、原测试容器及load转发进程已恢复，未修改公司的自动关机策略，未重建或删除旧卷。
